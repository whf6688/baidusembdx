# 百度搜索信息流系统级重构遗漏审计

审计日期：2026-09-15

审计范围：本地前端源码、后端回归、组件测试、浏览器测试、当前截图、项目路由和《广告系统UIUX组件设计规范》

审计边界：未连接线上服务器；未发布；未执行真实百度写入；未运行好多粉补采

## 一、结论

当前版本不能按“系统级重构全部完成”验收

核心业务规则和现有后端回归没有发现明显倒退；项目编码路径、账户工作区、自动上线四页签、自动策略和物料分页等主链路已经存在

但实现仍存在结构性未收口、视觉规范只通过覆盖层实现、刷新状态错误、多项目页面状态未完全隔离、可访问性不完整、验收证据范围不足等问题；此前 `EXECUTION.md` 中“机械拆分完成”“电商 UI 完成”“完整验收完成”的表述高于实际完成度，不能继续作为最终验收依据

## 三、详细证据

### A-01 前端机械拆分没有完成

- `frontend/src/App.tsx` 仍有 3,057 行、约 264 KB
- 账户管理、执行记录、自动搭建、创意中心、物料中心、数据报表、成员管理和设置等主要页面仍集中在同一个文件
- 旧账户列表仍在 `App.tsx:1182` 挂载；仅通过 `.legacy-account-table { display: none !important; }` 隐藏
- `AutomationPage`、`TrackingPage`、`AuditPage` 和 `LegacySettingsPage` 等旧页面函数仍保留在生产源码
- 现有自动化甚至只验证旧表“不可见”，没有验证旧实现已经移除

整改完成标准：`App.tsx` 只保留应用壳、路由和顶层数据装配；各业务页进入独立 feature；隐藏旧表和不可达旧页面从生产源码删除；旧状态和旧请求同时清理

### A-02 UI 规范没有形成单一设计系统

- `main.tsx` 依次加载 `styles.css` 和 `ecom-ui.css`；新版依赖后加载覆盖旧版
- `styles.css` 包含 51 个 `!important`、898 个十六进制颜色和 2,108 个 px 值
- `ecom-ui.css` 包含 453 个 `!important`、625 个十六进制颜色和 1,251 个 px 值
- `ecom-ui.css` 内有 4 个 `:root`；`.sidebar`、`.topbar`、`.page-heading` 等核心选择器被多轮重复定义
- 同一个控件最终样式取决于导入顺序、选择器权重和 `!important`，不符合规范要求的语义 Token 和稳定组件单一来源

整改完成标准：建立唯一 Token 层；页面不再直接散布主色、字号、行高、圆角和间距；合并或删除旧视觉层；同类按钮、筛选、表格、页签、分页和弹窗只使用共享组件

### A-03 全局刷新状态实现错误

- `App.tsx:187` 声明 `refreshing`
- 全项目没有任何 `setRefreshing(true)`
- `App.tsx:304` 点击刷新只增加 `reloadKey`
- 请求 effect 在 `App.tsx:224` 设置 `loading=true`；页面在 `App.tsx:307` 切换为全页 `LoadingView`
- `App.tsx:244` 只在结束时调用 `setRefreshing(false)`

实际结果：按钮不会显示“刷新中”；顶部不会进入“后台刷新中”；刷新期间旧数据消失；这与规范中“刷新保留旧数据并标记更新中”的要求相反

整改完成标准：首次进入使用 `loading`；手动刷新使用 `refreshing`；保留现有页面数据；只在请求成功后替换数据；失败时保留旧数据并弹窗提示

### A-04 原验收报告覆盖范围不足且部分证据标注错误

- 当前重新执行结果为后端 233 项通过、组件 8 项通过、浏览器 12 项通过、生产构建通过
- 12 项浏览器测试主要覆盖账户工作区、策略基本页签、自动上线模式卡片、执行节点、项目入口、报表空态、账户计划缓存和物料分页
- `project-management-1440.png`、`member-management-1440.png`、`strategy-project-refresh-1440.png` 实际尺寸均为 1280×720
- `material-pagination-1440.png` 不是本次测试重新生成；当前物料分页测试没有截图步骤
- 截图仅生成文件，没有视觉差异基线和像素回归断言
- 只有账户工作区覆盖 1366、1440、1920；不能据此推导所有页面在三种宽度均通过

整改完成标准：按页面和关键弹窗建立 1280、1366、1440、1920 的验收矩阵；截图名称与实际 viewport 一致；关键页面增加视觉差异检查；测试报告区分“已证明”和“未验证”

### A-05 1280 宽度项目首页不符合规范

- 当前实际 1280×720 截图中项目操作列右侧被截断
- “进入项目”主按钮出现蓝底深色文字的低对比状态
- 规范明确要求内部数据后台必须支持 1280 宽度

整改完成标准：1280 下项目名称、状态和全部操作可见；主按钮符合统一主色与白色文字；不依赖裁切隐藏操作

### A-06 工作台仍显示项目名称

- `App.tsx:2161` 创意中心说明拼接 `project.name`
- `App.tsx:2426` 物料中心说明拼接 `project.name`
- `App.tsx:2882` 自动策略说明拼接 `project.name`
- 不可达的监测中心和旧系统设置也保留同类写法

这与“通过 URL 项目编码确定上下文；工作台顶部不再重复显示项目”的要求不一致

整改完成标准：项目名称只在系统首页和需要确认跨项目操作的弹窗中出现；工作台页头只显示当前功能名称和功能说明

### A-07 去图标方式造成空白控件

- 源码仍为刷新、提醒、项目、导入、安全说明、自动上线、创意等按钮和区域传入图标
- CSS 统一隐藏图标后，右上角提醒入口在截图中变成只有红色“99+”角标的空白方框
- 这是把图标视觉隐藏，而不是重新设计无图标控件

整改完成标准：删除装饰图标属性和占位；提醒入口改为清晰文字按钮，例如“提醒 99+”；功能性搜索和日期图形需按规范单独决定，不使用全局隐藏

### A-08 多项目标签页状态没有完全隔离

- 项目路由已经使用 `/{项目编码}?page={页面}`；这是正确实现
- `uiTimeZone.ts` 仍使用全局键 `search-console.ui-timezone`
- 同一域名的多个项目标签共用该键；一个项目修改页面时区会立即影响另一个项目的显示

整改完成标准：时区以项目配置为唯一来源，或使用包含项目编码的键；浏览器标签不依赖其他项目最后一次写入的本地状态

### A-09 自动策略二级页签不能通过 URL 恢复

- `AutomaticStrategyPage` 的 `section` 默认固定为 `policies`
- “项目刷新”“参考模板”“运行状态”只存在组件内部 state
- 刷新浏览器或复制链接后会回到“策略管理”

整改完成标准：二级工作区写入 URL，例如 `page=strategies&section=refresh`；前进、后退、刷新和复制链接均恢复原位置

### A-10 弹窗与表格语义不统一

- 大部分弹窗使用 Fluent Dialog；删除账户管家却在 `AccountWorkspaceTable.tsx:160` 使用自制 `div[role=dialog]`
- 自制弹窗没有标准焦点陷阱、Esc 关闭和关闭后焦点恢复证据
- 项目列表使用普通 `div` 模拟表格；成员列表只有 `role=table/row`，表头和单元格缺少完整角色
- 可排序列没有一致的 `aria-sort`

整改完成标准：所有确认类弹窗统一使用 DialogShell 或 Fluent Dialog；所有数据表统一使用语义 table 或完整 ARIA Grid；键盘和读屏行为加入组件测试

### A-11 筛选器选中态不符合规范

- 成员状态、执行状态和执行动作等筛选直接使用 `appearance="primary"`
- 这会让筛选条件与“保存”“发布”“执行”等主操作拥有相同视觉等级

整改完成标准：状态筛选统一为 StatusFilterBar；选中态使用弱蓝背景、边框和文字；页面只保留一个主要动作层级

### A-12 后台节点编码仍可能直接显示

- `taskNodeText` 未命中映射时返回 `value.replaceAll('_', ' ')`
- 当前浏览器样本使用 `current_node=adgroups`；该值没有显式中文映射
- 执行记录可能出现 `adgroups`、未知 task type 或其他内部枚举

整改完成标准：前端使用后台返回的显示文案或完整枚举映射；未知值显示“未知节点”并保留技术详情到可展开区域，不直接作为主结果文案

### A-13 账户管理存在可见截断

- `account-managers-1440.png` 中“类型”值“账户管家”显示为“账...”
- 当前表格对所有单元格统一启用 `overflow:hidden` 和省略号；类型、状态、返点等短字段也会被错误截断

整改完成标准：短枚举列保证完整显示；只允许账户名、充值账户等长文本列省略；省略内容提供 title 或详情入口

### A-14 装饰图标没有从组件中移除

- `App.tsx` 仍导入十余个 Fluent 图标并在多个页面渲染
- 旧页面和旧图标样式继续留在生产包
- 全局隐藏图标已造成提醒入口空白；后续新组件仍可能继承不一致行为

整改完成标准：逐组件清理装饰图标和无效 CSS；保留的功能性图形必须有可访问名称且不占用被隐藏的空位

### A-15 浏览器测试缺少关键业务交互

当前未证明的主要场景：

- 全局刷新保留旧数据、成功和失败提示
- 两个项目在两个标签中同时操作且状态不串项目
- 全局提醒缩略信息、全文弹窗、全部已读、余额和任务提醒
- 项目新建、编辑、启停和非法编码校验的完整提交
- 管家授权、同步、余额读取、删除存档的前端闭环
- 账户跨行多选、跨页选择、批量设置、批量时段、暂停和启用
- 自动搭建多日期×多时间、不限日期队列、指定主体模糊搜索和提交确认
- 创意中心新增、去重、随机组合、审核同步和黑名单
- 物料导入、A–F 规则编辑、黑名单、否词模板复制和风险确认
- 有真实样本数据的报表筛选、排序、分页、导出和水位提示
- 1280 全站布局、200% 缩放、完整键盘操作、焦点陷阱、减少动画和颜色对比

整改完成标准：每个旧功能在功能映射中对应一个自动化证据；每个高风险写入口至少覆盖预检、取消、确认、失败和幂等反馈
