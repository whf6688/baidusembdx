## 行为边界

- 预算重置只处理启用、未淘汰、测试期、预算快照在 60 分钟内且当前预算不等于已发布固定金额的账户；命中后直接写入该固定金额。
- 预算追加原判断为加粉数 > 0、成本 < 100、利用率 > 0.8，追加 50；不新增边际算法。
- 淘汰保持累计消费 > 100 且无加粉，或累计加粉成本 > 120；保留当前执行与回读。
- 充值提醒保持主体 + 钱柜分组及 7 天消费、余额支撑不足 2 天的现行规则。
- 原投放工作流、A–F 优选分配、5,000 词拆分、多日期/时间队列、参考模板、关键词参数不改；新增全量模式只取消 A–F 筛选，不绕过黑名单与安全链路。
- 独立搜索授权中心优先于共享资料中的旧版共用应用描述。
- 后台统一计算指标，不改变日报粒度和导出语义。
- 项目选择不是工作台内的全局切换器；系统首页为 `/`，已进入的项目使用 `/{项目编码}?page={页面}`；例如 `/jfsem?page=account-list`
- 项目编码位于路径而不是浏览器本地状态；因此复制、刷新、前进后退和新开浏览器标签都会保持各自项目上下文
- 左侧“系统设置”与“项目与账户”同级；系统登录成员进入“成员管理”，项目刷新、参考模板、运行状态进入“自动策略”；全局刷新位于页面右上角。
- 不改变线上配置、现有本地 .env、身份权限、Token、缓存、限频、幂等和保护条件。

## 基线与验证

源码基线通过 `node scripts/refactor-baseline.mjs` 写入本项目 data/refactor/baselines；归档不包含数据、环境文件或密钥。验证命令仅针对本地测试/构建，不执行发布。

组件测试使用固定样本和完全模拟的业务请求。浏览器测试连接本地 API 验证真实大账户量页面；最终重建了本地 Worker 与 scheduler，日志确认验收期间到期写任务为 0。未主动提交真实百度写入或好多粉补采。
